# アップロード履歴

**Upload History** ページでは、Workflow で実行されたすべての一括ファイルアップロード操作の履歴を一元的に確認できます。

このページを使うことで、管理者はアップロードの進捗状況を監視し、完了したインポートを確認し、失敗したアップロードを特定して、インポートの問題を調査できます。

代表的なアップロード操作には、以下が含まれます。

- Employee Import
- Timesheet Import
- Leave Balance Import
- その他の一括インポート処理

![Upload History](/images/upload-history-list.png)

---

## 概要

ファイルが送信されると、各アップロード操作は自動的に記録されます。

Upload History ページでは、管理者は以下を行うことができます。

- アップロードの進捗を確認する。
- アップロード記録を検索する。
- アップロード履歴を絞り込む。
- 処理ステータスを監視する。
- アップロード日時を確認する。
- 失敗したインポートの error log をダウンロードする。

---

## Upload History 一覧

各アップロード記録には、以下の情報が含まれます。

| 列            | 説明                             |
| --------------- | ---------------------------------- |
| Status         | アップロードの現在の処理ステータス。 |
| Process Name   | 自動生成される処理の識別子。        |
| File Name      | アップロードされたファイル名。      |
| Upload Date    | アップロードが送信された日時。      |

![Upload History List](/images/upload-history-list.png)

---

## アップロードのステータス

各アップロード操作は、以下のいずれかのステータスを経て処理されます。

| ステータス     | 説明                                                                 |
| -------------- | ----------------------------------------------------------------------- |
| **Pending**    | アップロード要求を受け付け、処理待ちの状態です。                       |
| **Uploading**  | ファイルの検証とシステムへのインポートが進行中です。                   |
| **Done**       | アップロードが正常に完了しました。                                     |
| **Failed**     | 検証エラーまたは処理エラーにより、アップロードを完了できませんでした。 |

<Callout type="info">
  アップロードのステータスは、インポート処理の進行に応じて自動的に更新されます。
</Callout>

---

## アップロード記録の検索

検索ボックスを使うと、過去のアップロード操作をすばやく見つけることができます。

以下の項目で検索できます。

- Process Name
- File Name

入力すると同時に、アップロード履歴が即座に絞り込まれます。

---

## アップロード履歴のフィルター

**Filter** を選択すると、アップロード履歴を絞り込むことができます。

![Upload History Filter](/images/upload-history-filter.png)

利用可能なフィルター:

| フィルター    | 説明                                             |
| -------------- | -------------------------------------------------- |
| Upload Date    | 特定の日に送信されたアップロードを表示。          |
| Status         | 1つまたは複数の処理ステータスでアップロードを表示。 |

複数のステータス値を同時に選択できます。

例:

- Pending
- Uploading
- Failed

---

## Error Log

アップロードが失敗すると、Workflow は error log を生成します。

**Error log** を選択すると、検証エラーまたは処理エラーの内容を確認できます。

error log は、管理者が以下を行う際に役立ちます。

- 不正なレコードを特定する。
- インポートデータを修正する。
- 修正したファイルを再アップロードする。

<Callout type="warning">
  Error log は、**Failed** ステータスのアップロード操作でのみ利用できます。
</Callout>

## 一般的なアップロードの流れ

以下のフローは、標準的な一括アップロード処理を示しています。

<Steps>

### Upload File

インポート用のファイルを選択してアップロードします。

### Validation

Workflow が、アップロードされたファイルの形式と内容を検証します。

### Processing

システムが、有効なレコードを Workflow にインポートします。

### Complete

アップロードは、以下のいずれかの結果で終了します。

- **Done**
- **Failed**

アップロードが失敗した場合、管理者は error log を確認し、元のファイルを修正した上で再度アップロードできます。

</Steps>

## 業務ルール

<Accordions>

<Accordion title="すべてのアップロードは記録されますか?">

はい。

成功・失敗にかかわらず、すべての一括アップロード操作は自動的に Upload History に記録されます。

</Accordion>

<Accordion title="処理中のアップロードを監視できますか?">

はい。

Status 列は、アップロードが各処理段階を進むごとに自動的に更新されます。

</Accordion>

<Accordion title="複数のアップロードを同時に処理できますか?">

はい。

各アップロードは個別に追跡され、Upload History にそれぞれ独立した記録として表示されます。

</Accordion>

<Accordion title="アップロードが失敗した理由を確認できますか?">

はい。

失敗したアップロードには **Error log** が付属し、検証エラーまたは処理エラーの詳細を確認できます。

</Accordion>

</Accordions>
