# 組織図

<Callout type="info">
**組織図(Organization Chart)** は、部署、報告関係、部署代表者を含む会社の組織階層を定義します。

Workflow は、現在有効な組織図を使用して、承認ルーティング、申請の表示範囲、部署管理など、組織構造に依存するあらゆる機能における組織間の関係を判断します。

</Callout>

## 概要

組織図を使用すると、管理者は過去のバージョンを保持しながら、会社の組織構造を構築・維持できます。

既存のデータを上書きする従来の組織図とは異なり、Workflow は組織構造の変更ごとに**バージョン(Version)**として保存します。これにより、現在の組織に影響を与えることなく、将来の組織変更を事前に準備できます。

組織図モジュールから、管理者は以下を行うことができます。

- 新しい組織図を作成する。
- 複数の組織図バージョンを管理する。
- 組織図が有効になる時期をスケジュールする。
- 過去の組織構造を確認する。
- 部署とその階層を管理する。
- 部署に従業員を割り当てる。
- 部署代表者を設定する。
- 既存の組織図を複製して再利用する。

## 組織図のライフサイクル

各組織図は、特定の時点における会社の組織構造のスナップショットを表します。

一般的なライフサイクルは以下のとおりです。

```text
作成
   │
   ▼
Editing
   │
   ▼
Not in use
   │
   ▼
In use
   │
   ▼
End
```

このバージョンベースの方式により、管理者は Workflow が現在使用している組織図に影響を与えることなく、将来の組織変更を安全に準備できます。

---

## 組織図一覧

組織図一覧には、会社に作成されたすべての組織構造が表示されます。

各組織図には、以下の基本情報が含まれます。

| 列                          | 説明                                     |
| --------------------------- | ---------------------------------------- |
| Status(ステータス)          | 組織図の現在のライフサイクルステータス。 |
| Name(名前)                  | 組織図の名前。                           |
| Applied Date(適用日)        | 組織図が有効になる日時。                 |
| Updated Date Time(更新日時) | 最終更新日時。                           |
| Action(操作)                | 組織図に対して利用可能な操作。           |

## 組織図のステータス

組織図は、4つの状態のいずれかを取ります。

| ステータス     | 説明                                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| **Editing**    | 組織図が作成・編集中の状態です。確定する前であれば、管理者は部署、従業員、階層を自由に変更できます。       |
| **Not in use** | 組織図は完成していますが、まだ有効化されていません。次の有効な組織構造として使用できる準備が整っています。 |
| **In use**     | 組織図が Workflow 全体で現在使用されています。組織に依存するすべての機能がこの組織図を参照します。         |
| **End**        | 組織図はもう有効ではなく、過去の記録として保持されます。                                                   |

<Callout type="warning">
  ある時点において、**In use** 状態になれる組織図は <strong>1つだけ</strong>
  です。
</Callout>

---

## ステータスの遷移

組織図のライフサイクルは、以下のプロセスに従います。

```text
Editing
     │
     ▼
Not in use
     │
     ▼
In use
     │
     ▼
End
```

新しい組織図が有効化されると、Workflow がステータスの遷移を自動的に管理します。

例:

- 新規作成された組織図は **Editing** から始まります。
- 完成すると、スケジュール設定または有効化ができます。
- 有効化されると **In use** になります。
- それまで有効だった組織図は自動的に **End** になります。

---

## バージョン管理

組織図は上書きされるのではなく、バージョンとして管理されます。

部署の再編、組織統合、報告ラインの更新など、組織構造が変更される場合は、現在有効な組織図を直接編集するのではなく、新しい組織図を作成することが推奨されます。

この方式には、以下のメリットがあります。

- 過去の組織構造を保持できる。
- 有効になる前に組織変更を準備できる。
- 業務上のリスクを低減できる。
- 将来の組織計画を支援できる。

一般的な流れ:

```text
現在の組織図(In use)
        │
        ▼
複製(Duplicate)
        │
        ▼
新しい組織図(Editing)
        │
        ▼
部署を更新
従業員を更新
階層を更新
        │
        ▼
Applied Date を設定
        │
        ▼
有効化
        │
        ▼
以前の組織図 → End
```

<Callout type="tip">
  既存の組織図を **Duplicate(複製)** することは、既存の階層を維持したまま
  必要な部署だけを変更できるため、組織変更を準備する際に推奨される方法です。
</Callout>

## 適用日(Applied Date)

各組織図には、その組織図が有効になる時期を示す **Applied Date** が設定されています。

作成日とは異なり、Applied Date は Workflow がその組織構造の使用を開始するタイミングを制御します。

これにより、管理者は組織変更を事前に準備できます。

例:

```text
今日
 │
 ├── 組織図を作成
 │
 ├── 部署を設定
 │
 ├── 従業員を設定
 │
 └── Applied Date = 来週の月曜日

現在の組織図
        │
        ▼
そのまま有効な状態を維持

来週の月曜日
        │
        ▼
新しい組織図が In use になる
```

この仕組みにより、日常業務を中断することなく、スケジュールされた日に組織再編が自動的に行われます。

## 業務ルール

<Accordions>

<Accordion title="複数の組織図を同時に有効にできますか?">

いいえ。

Workflow では、**In use** 状態になれる組織図は1つだけです。別の組織図を有効化すると、それまで有効だった組織図は自動的に終了します。

</Accordion>

<Accordion title="新しい組織図を編集すると、現在の組織に影響しますか?">

いいえ。

**Editing** または **Not in use** 状態の組織図への変更は、その組織図が有効化されるまで、現在の組織構造に影響しません。

</Accordion>

<Accordion title="以前の組織図はどうなりますか?">

以前の組織図が上書きされることはありません。新しい組織図に置き換えられると、**End** 状態に移行し、過去の記録として参照できます。

</Accordion>

<Accordion title="新しい組織図を作成すべきですか、それとも現在有効な組織図を編集すべきですか?">

現在有効な組織を直接編集するのではなく、有効な組織図を複製して新しいバージョンを作成することを推奨します。

</Accordion>

</Accordions>
